# 計算条件の報告と再現パッケージ (`adit-report`) / Reporting settings and reproducibility packages

`adit-report` は、ADIT が生成した計算ディレクトリから **論文や報告書の「方法」の節**、**条件の表 (CSV)**、
**再現に要るファイル一式**を書き出します。**書くのは記録に残っている事実だけです。**
値は生成した `spec.json` (作成時の記録つき) と `code_version.txt` (実際に走った計算コードのバージョン) から取り、
記録が無いものは「未記録」と書きます。推奨値や、ADIT が確かめていない説明は足しません。

`adit-report` turns a directory generated by ADIT into **a methods section** for a paper or report, **a settings table (CSV)**,
and **a package with the files needed to reproduce the run**. It writes **only what is on record**:
values come from `spec.json` (with provenance) and `code_version.txt` (the version of the code that actually ran).
Anything not on record is marked as not recorded; no recommended values are added.

## 使い方

```bash
adit-report run1 run2 ... -o methods.md --lang both   # 方法の節 (日英)
adit-report run1 run2 ... --csv conditions.csv        # 条件を 1 枚の表に (補足資料用)
adit-report run1 --bundle pack.zip                    # 再現パッケージ (.zip かディレクトリ)
adit-report run1 run2 ... --results-csv results.csv    # 結果 (エネルギー・温度・正常終了) を 1 枚の表に
adit-report run1 --check                              # 入力・擬ポテンシャル・力場が生成後に変わっていないか
```

`--csv` は**条件**の表、`--results-csv` は**結果**の表です (最終エネルギー [eV]、平均温度 [K]、フレーム数、
振動数の本数、正常終了と収束、状態)。状態の欄には `not_run` (まだ走っていない)、`unreadable` (読めない)、`read` が入ります。

`--lang` は `ja` / `en` / `both` (日本語のあとに英語) です。省略すると ADIT の設定の言語になります。
`--check` は、書き換えられたファイルか、無くなったファイルがあると終了コード 1 を返します
(スクリプトの中で「条件が記録どおりか」を確かめられます)。

`--lang` takes `ja`, `en` or `both`; omit it to use adit's language setting. `--check` exits with status 1 when a file
was changed or is missing, so it can gate a script.

## 方法の節に入るもの

| 節 | 中身 | 出典 |
|---|---|---|
| 本文 | 組成・原子数・周期性・電荷・多重度、計算コードとバージョン、計算の種類、入力を生成した ADIT のバージョンと日時 | `spec.json`、`code_version.txt` |
| 条件の表 | `method.*` / `task.*` / `kpoints.*` の値と単位 | `spec.json` |
| 照合用のハッシュの表 | 生成した入力・写したパラメータ・書き写したファイルの SHA-256 | `spec.json` の `provenance` |
| 入力に書かれない共通の欄 | 値と、書かれない理由 (`adit.applied` の一覧) | `spec.json` + 生成器の実装 |
| 実行のしかた | プロセス数・スレッド数・walltime (機種・OS・コンパイラは記録していません) | `spec.json` の `runtime` |
| 結果の要約 | `adit-analyze` が書いた要約をそのまま (あるときだけ) | `analysis/summary.txt` |
| 記録が無いもの | バージョンが未記録、作成時の記録が無い、など | 上が欠けているとき |

**この表は `spec.json` の記録であって、計算コードの入力に実際に書かれたかは別です。**
共通の欄 (たとえば `task.optimizer`) には、コードによって入力へ写されないものがあります。
実際に書かれた項目だけを照合するには `adit-convert verify <ディレクトリ>` を使ってください。

**The table is what `spec.json` records, not proof of what was written into the code's input.** Some shared fields are not
carried into every code. To compare only the settings that were actually written, use `adit-convert verify <directory>`.

単位は欄の名前の末尾から引きます (`_ha` → Hartree、`_ev_per_ang` → eV/Å、`_fs` → fs、`_k` → K …)。
`method.*` の値が 0 の欄は、ADIT では「指定しない (入力に書かない)」の意味なので表に出しません
(乱数の種だけは 0 も値として出します)。

## ファイルの照合 (`--check`)

生成のときに、ADIT は入力ファイルの SHA-256 を `spec.json` の `provenance.inputs` に残します。
`--check` は、それといまのファイルを突き合わせて「同じ / 書き換え / ありません」を出します。

- **同じ** —— 生成したときのままです
- **書き換え** —— 生成したあとで中身が変わっています。この計算の条件は `spec.json` の記録と違うかもしれません
- **ありません** —— ファイルが消えています

見るのは ADIT が生成した入力だけでなく、**写した擬ポテンシャル・力場・トポロジー**と、書き写して作ったファイルも含みます。
終了コードは **0 = すべて一致 / 1 = 書き換えか欠落あり / 2 = 照合用のハッシュの記録が無くて確かめられない** の 3 つです
(「確かめられない」を合格と同じにしません)。照合用のハッシュの記録が無いのは、記録を残す前の版の ADIT で生成したか、
`spec.json` の作成時の記録が失われた場合です。

At generation time ADIT stores the SHA-256 of every input file under `provenance.inputs` in `spec.json`. `--check`
compares those with the files on disk and reports *same* / *changed* / *missing*. It covers not only the generated
inputs but also **the copied pseudopotentials, force fields and topologies** and the files derived from them.
The exit status is **0 = everything matches / 1 = something changed or is missing / 2 = no fingerprints on record,
so nothing can be checked** ("cannot check" is never treated as a pass). Fingerprints are missing when the directory
was generated by a version of ADIT that did not record them yet, or when the provenance in `spec.json` was lost.

## 再現パッケージ (`--bundle`)

入っているもの: `methods.md`、`manifest.json`、計算ごとに `spec.json` / `README.txt` / `submit.sh` /
入力ファイル / 写したパラメータ / `code_version.txt` (あれば)。**計算の出力は入れません** (大きく、再現の入力ではないため)。
`manifest.json` には、再現パッケージを作ったときに計算した SHA-256 と、生成時に記録した SHA-256 の両方と、その一致 (`state`) が入ります。

`.zip` を指定すると zip、それ以外はディレクトリになります。**すでにあるものには書きません** (黙って上書きしません)。

The package contains `methods.md`, `manifest.json`, and per run: `spec.json`, `README.txt`, `submit.sh`, the input files,
the copied parameter files, and `code_version.txt` when it exists. **Outputs are not included** (they are large and are not
the inputs needed to reproduce). `manifest.json` records both the SHA-256 computed when the package was made and the one
stored at generation, plus whether they match. A `.zip` destination writes a zip, anything else a directory; an existing
path is never overwritten.

## 例

```bash
$ adit-report examples/prep_stage1_dftb_continue_nve examples/prep_stage2_dftb_adsorption/molecule --check
examples/prep_stage1_dftb_continue_nve: 生成したときの照合用のハッシュと突き合わせました (6 件)
  同じ      skf/H-H.skf  (写したファイル)
  同じ      skf/H-O.skf  (写したファイル)
  同じ      skf/LICENSE  (写したファイル)
  同じ      skf/O-H.skf  (写したファイル)
  同じ      skf/O-O.skf  (写したファイル)
  同じ      skf/README  (写したファイル)
  → すべて生成したときのままです
examples/prep_stage2_dftb_adsorption/molecule: 生成したときの照合用のハッシュと突き合わせました (6 件)
  同じ      skf/H-H.skf  (写したファイル)
  ...
  → すべて生成したときのままです
```

方法の節の 1 段落目はこの形です (値はすべて記録から)。

> H2O (3 原子、非周期 (孤立した分子)、全電荷 0、スピン多重度 1) について、Psi4 (psi4 1.11) を用いて構造最適化を
> 行いました。バージョンは計算の出力から写したものです。入力は ADIT 0.0.1 が 2026-09-13T…Z (UTC) に生成しました。
