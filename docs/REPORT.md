# Reporting settings and reproducibility packages (`adit-report`)

`adit-report` turns a directory generated by ADIT into **a methods section** for a paper or report, **a settings table (CSV)**,
and **a package with the files needed to reproduce the run**. **It writes only what is on record.**
Values come from the generated `spec.json` (with provenance) and `code_version.txt` (the version of the code that actually ran).
Anything not on record is marked "Not on record". No recommended values, and no explanations that ADIT has not verified, are added.

## Usage

```bash
adit-report run1 run2 ... -o methods.md --lang both   # methods section (Japanese and English)
adit-report run1 run2 ... --csv conditions.csv        # settings in one table (for supplementary material)
adit-report run1 --bundle pack.zip                    # reproducibility package (.zip or a directory)
adit-report run1 run2 ... --results-csv results.csv    # results (energy, temperature, normal termination) in one table
adit-report run1 --check                              # whether inputs, pseudopotentials and force fields changed after generation
adit-report run1 run2 ... --bib references.bib        # the references the methods section cites, as BibTeX
```

`--csv` writes the **settings** table and `--results-csv` the **results** table (final energy [eV], mean temperature [K], number of frames,
number of frequencies, normal termination and convergence, state). The state column holds `not_run` (not run yet), `unreadable` (cannot be read) or `read`.

`--lang` takes `ja`, `en` or `both` (Japanese followed by English). If omitted, ADIT's language setting is used.
`--check` exits with status 1 when a file was changed or is missing
(so a script can confirm that the settings match the record).

## What the methods section contains

| Section | Contents | Source |
|---|---|---|
| Body text | Composition, number of atoms, periodicity, charge, multiplicity, code and version, calculation type, and the ADIT version and date that generated the input | `spec.json`, `code_version.txt` |
| Settings table | Values and units of `method.*` / `task.*` / `kpoints.*` | `spec.json` |
| Fingerprint table | SHA-256 of generated inputs, copied parameter files and files derived from other files | `provenance` in `spec.json` |
| Shared fields not written into the input | Values and the reason they are not written (the list in `adit.applied`) | `spec.json` + the generator implementation |
| How it was run | Number of processes, number of threads, walltime (machine type, OS and compiler are not recorded) | `runtime` in `spec.json` |
| Results summary | The summary written by `adit-analyze`, as is (only when present) | `analysis/summary.txt` |
| References to cite | The BibTeX keys to cite, and items whose reference is not on record (see "References to cite" below) | `method` in `spec.json` + each code's official page |
| Not on record | Version not recorded, no provenance, and so on | When any of the above is missing |

**The table is what `spec.json` records, not proof of what was written into the code's input.**
Some shared fields (`task.optimizer`, for example) are not carried into the input of every code.
To compare only the settings that were actually written, use `adit-convert verify <directory>`.

Units are looked up from the end of the field name (`_ha` → Hartree, `_ev_per_ang` → eV/Å, `_fs` → fs, `_k` → K …).
Among the `method.*` fields, those where 0 means "not set (not written into the input)" (cutoff, number of bands, amount of memory, position of the dipole correction and so on)
are left out of the table when the value is 0. Fields where 0 has a meaning (`ismear = 0` and `ibrion = 0` in VASP, `md_shake = 0` in xtb and so on) and random seeds appear even at 0.

## Checking files (`--check`)

At generation time, ADIT stores the SHA-256 of the input files under `provenance.inputs` in `spec.json`.
`--check` compares those with the current files and reports "same", "changed" or "missing".

- **same**: the file is as generated
- **changed**: the contents changed after generation. The settings of this calculation may differ from the record in `spec.json`
- **missing**: the file is gone

The check covers not only the inputs ADIT generated but also **the copied pseudopotentials, force fields and topologies** and the files derived from them.
The exit status is one of three: **0 = everything matches / 1 = something changed or is missing / 2 = no fingerprints on record, so nothing can be checked**
("cannot check" is never treated as a pass). Fingerprints are missing when the directory was generated by a version of ADIT that did not record them yet,
or when the provenance in `spec.json` was lost.

## References to cite (`--bib`)

Each run's section in the methods ends with a **"Cite: …"** line listing BibTeX keys. `--bib references.bib` writes the full entries
(`references.bib` is also included in `--bundle`). **Only keys looked up from the record are listed**, and they are collected in this order.

| Reference for | Source | Field on record |
|---|---|---|
| Calculation code | Each code's official "please cite" page (table below) | `method.code` |
| Slater-Koster set | "Required references" in the README of each set at dftb.org (mio, 3ob, pbc, matsci, ob2, tiorg, trans3d, halorg, magsil, znorg, auorg, siband, borg) | First word of `method.sk_set` |
| Pseudopotential set | SSSP (Materials Cloud), pslibrary (official page) | Words contained in `method.pseudo_set` |
| Functional | PBE (and its erratum), PBEsol, B3LYP | `method.xc` / `input_dft` / `method.method` / `GGA` in VASP (otherwise the POTCAR set name) / `xc` in OpenMX. For QE without `input_dft`, the header of the UPF in `pseudo/` |
| Dispersion correction | DFT-D3, D3(BJ), DFT-D4 (README of dftd3 / dftd4) | `dispersion = dftd3` in DFTB+ (written with BJ damping), `dispersion` in CP2K, `IVDW` in VASP (11 / 12 / 13), D3 / D3BJ / D4 in `method` and `extra_keywords` of ORCA |
| GFN in xtb | The GFN1 / GFN2 / GFN-FF papers (README of xtb) | `method.gfn` |
| ADIT itself | `CITATION.cff` in the repository, converted to `@software` | — |

References verified on each code's official page (as of 2026-09-19):

| Code | Official page | Keys |
|---|---|---|
| DFTB+ | dftbplus.org/about (J. Phys. Chem. A, 2025) and the GitHub README (J. Chem. Phys., 2020) | `dftbplus_hourahine2025`, `dftbplus_hourahine2020` |
| VASP | Developer's answer "How to cite VASP" in the vasp.at forum | `vasp_kresse1993`, `vasp_kresse1994`, `vasp_kresse1996a`, `vasp_kresse1996b`; for PAW, `vasp_kresse1999` |
| Quantum ESPRESSO | Terms of use in the user guide | `qe_giannozzi2009`, `qe_giannozzi2017` |
| xtb | Citations in the GitHub README | `xtb_bannwarth2020` + the GFN papers |
| ORCA | How to Cite in the ORCA 6.1 manual (a list for each calculation is also at the end of the output) | `orca_neese2012`, `orca_neese2025` |
| CP2K | FAQ "How to cite" at cp2k.org (see also the REFERENCES section of the output) | `cp2k_kuhne2020` |
| LAMMPS | Citing LAMMPS at docs.lammps.org | `lammps_thompson2022` |
| GROMACS | Citation information in the reference manual (of the 8 papers, the 1993 conference proceedings, which has no DOI, is left out) | `gromacs_abraham2015` and 6 others |
| OpenMM | Referencing OpenMM in the user guide (currently only the OpenMM 8 paper) | `openmm_eastman2024` |
| Psi4 | Citing Psi4 in the manual | `psi4_smith2020` |
| ABINIT | Acknowledgments at docs.abinit.org (the 2025 paper is required, the two 2020 papers are strongly recommended) | `abinit_verstraete2025`, `abinit_gonze2020`, `abinit_romero2020` |
| NWChem | Citation at nwchemgit.github.io | `nwchem_apra2020` |

**Other codes (Gaussian, GAMESS, Q-Chem, GRRM, OpenMX, Amber, NAMD, DC-DFTB-MD, machine-learning potentials) have not been verified,
so the output says "Not on record: reference for the code …".** Functionals and dispersion corrections not in the table above (BLYP, PBE0, TS and so on) are also not on record.
**ADIT does not choose references.** It only maps recorded names to the instructions on the official pages, and makes no judgment such as "these settings should also cite this".
Add any further citations for the features you used (those ORCA and CP2K write in their output, the Zenodo DOI of each GROMACS release and so on) yourself.

## Reproducibility package (`--bundle`)

The package contains `methods.md`, `manifest.json`, `references.bib`, and for each run: `spec.json`, `README.txt`, `submit.sh`,
the input files, the copied parameter files, and `code_version.txt` (when it exists). **Calculation outputs are not included** (they are large and are not inputs for reproduction).
`manifest.json` records both the SHA-256 computed when the package was made and the SHA-256 recorded at generation, and whether they match (`state`).

A `.zip` destination writes a zip, and anything else a directory. **It never writes to something that already exists** (no silent overwriting).

## Example

```bash
$ adit-report examples/prep_stage1_dftb_continue_nve examples/prep_stage2_dftb_adsorption/molecule --check
examples/prep_stage1_dftb_continue_nve: compared with the fingerprints recorded at generation (6 files)
  same      skf/H-H.skf  (copied file)
  same      skf/H-O.skf  (copied file)
  same      skf/LICENSE  (copied file)
  same      skf/O-H.skf  (copied file)
  same      skf/O-O.skf  (copied file)
  same      skf/README  (copied file)
  → all files are as generated
examples/prep_stage2_dftb_adsorption/molecule: compared with the fingerprints recorded at generation (6 files)
  same      skf/H-H.skf  (copied file)
  ...
  → all files are as generated
```

The first paragraph of the methods section looks like this (all values come from the record).

> For H2O (3 atoms, nonperiodic (an isolated molecule), total charge 0, spin multiplicity 1), a geometry optimization was carried out
> with Psi4 (psi4 1.11). The version was copied from the output of the run. The input was generated by ADIT 0.1.0a1 on 2026-09-13T…Z (UTC).
