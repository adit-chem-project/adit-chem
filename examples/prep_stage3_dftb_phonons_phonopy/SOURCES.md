# Run of phonons (finite displacement, phonopy 4.5.0) — DFTB+ 25.1, mio-1-1 (2026-09-12)

## What this example is

Same diamond primitive cell as `prep_stage3_dftb_phonons_ase` (2 C atoms, a = 3.567 Å, lattice not relaxed), same 2×2×2 supercell and
DFTB+ settings, with the displacements made by phonopy. phonopy reduces displacements by symmetry, so there is 1 calculation (disp-001).
Generated by calling, through the API, the same process as `adit-gen spec.json out/ --phonons 2x2x2 --phonon-backend phonopy --phonon-dos-mesh 10x10x10` (`src/adit/phonon_setup.py`),
run, and then collected with `python phonon_collect.py`.

- phonopy is not an ADIT dependency. For this run, phonopy 4.5.0 (PyPI, BSD-3-Clause) was installed in a temporary location on the development machine
  (it declares phonors, symfc, PyYAML, h5py, spglib and others as dependencies; `pip install phonopy` installs them together)
- The primitive cell and the displacement are phonopy defaults. DOS uses q-points 10×10×10 (chosen for this example) with the phonopy default tetrahedron method.
  phonopy warned that the half-shift of an even mesh does not preserve the point group of the primitive cell, so it turned off symmetry reduction
- DOS on the default phonopy mesh (49×49×49 for this lattice) exceeded a 1.5 GB memory limit and was stopped the same day. ADIT does not produce a DOS on the default
  mesh (only when a mesh is given)
- Checked that the analysis reader (`src/adit/analysis/phonons.py`) can read band.yaml and total_dos.dat

## Results (numbers only; no judgment on stability)

Path GXWKGLUWLK,UX, frequencies 0.0003847 to 41.74 THz, 0 negative values.
This does not match the result collected along the ASE Phonons route (no phonopy) with the same DFTB+ settings (−4.275 to 44.68 THz, 24 negative values).
The cause of the difference was not checked (guess: ASE Phonons does not use symmetry, and treats periodic images at the edge of a small supercell differently from phonopy).
